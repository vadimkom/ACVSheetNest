# Протокол движка раскладки SheetNest

Как SheetNest вызывает внешний движок раскладки и что ждёт от него обратно. Так подключены `sparrow.exe`
(Sparrow на jagua-rs) и `rnest-sparrow.exe` (наш RNest). Любая программа, которая принимает такой же
`job.json` и пишет такой же `final_job.json`, встаёт на их место без изменений в SheetNest.

Код: `DeepNestSharp/RasterNest/SparrowNestService.cs`.

| Что | Где |
|---|---|
| файл задания | `BuildJaguaJson` |
| запуск | `RunSparrowOnce` |
| гонка попыток | `PackOneSheet` |
| разбор ответа | `MapAndCompact`, `ParseDensity` |

## 1. Задача движка в двух словах

Это **упаковка в полосу** (strip packing), не раскладка на лист:

- Полоса имеет фиксированную высоту `strip_height` по оси Y и бесконечную длину по X.
- Надо положить **все** экземпляры всех деталей (`demand`) без наложений.
- Каждая деталь лежит в одной из разрешённых ориентаций и целиком внутри `0 ≤ y ≤ strip_height`.
- Цель — минимальная длина занятой полосы по X (`strip_width`).

Лист, поля, зазоры, отверстия, общий рез и выбор листа делает SheetNest; движок их не видит.

- **Зазор уже заложен в контуры.** Каждый контур в задании расширен наружу на половину зазора детали.
  Поэтому контуры могут **касаться**, но не перекрываться: касание и даёт ровно нужный зазор.
- **Поля листа уже вычтены.** `strip_height` равна высоте листа минус два поля. Иногда к ней прибавлен
  ещё один зазор, чтобы деталь во всю высоту поместилась (см. комментарий перед `BuildJaguaJson`).
- **Ориентацию листа SheetNest выбирает сам.** Длинную сторону листа он кладёт по X (стоячий лист
  поворачивается, `StandingSheets.cs`). Для резки справа налево он зеркалит задание (`CutDirection.cs`).
  Движок всегда видит одну и ту же постановку: полосу вдоль X.
- **Отверстий в задании нет.** Мелкие детали в отверстия крупных SheetNest кладёт сам, уже после движка.

## 2. Какой exe запускается

`MainWindow.ResolveSparrowExe`, по порядку:

1. переменная окружения `SHEETNEST_SPARROW`, если указывает на существующий файл. **Так проще всего
   подключить свой движок, ничего не пересобирая**;
2. `rnest-sparrow.exe` рядом с `SheetNest.exe`, если в меню кнопки «▶ Nest» выбран RNest;
3. `sparrow.exe` рядом с `SheetNest.exe`.

В тестах и бенчах exe задаёт переменная `SPARROW_EXE`.

## 3. Запуск

На каждую попытку SheetNest создаёт **свою пустую папку** (`…\tryN`), делает её рабочей
(`WorkingDirectory`) и запускает:

```
<engine.exe> -i <полный путь к job.json> --max-iterations N -x -s SEED --workers W [флаги профиля] [SHEETNEST_SPARROW_ARGS]
```

| Флаг | Значение у Sparrow | Обязателен ли смысл для своего движка |
|---|---|---|
| `-i`, `--input` | путь к заданию (лежит **не** в рабочей папке, а уровнем выше) | да |
| `--max-iterations N` | бюджет поиска в итерациях. Draft = 100, Nest = 300, «последний шанс» = 600 (`nest-profiles.json`) | желательно: мерило «быстро / тщательно». RNest: < 400 — один проход, иначе генетический поиск |
| `-s SEED` | зерно генератора. SheetNest гоняет несколько зёрен и берёт лучшее | желательно: при одном и том же зерне ответ должен быть одинаковым |
| `-x` | остановиться, если поиск застрял | можно игнорировать |
| `--workers W` | потоков внутри процесса (обычно 1) | можно игнорировать |
| `--shrink-step`, `--max-fails`, `--compress-share`, `--no-improve-limit` | тонкие настройки Sparrow из профиля Draft/Nest | можно игнорировать |
| `--compress-step`, `--strike-limit`, `-t`, `-e`, `-c` | прочие флаги Sparrow | можно игнорировать |

**Неизвестные флаги нельзя считать ошибкой**: их можно передать через `SHEETNEST_SPARROW_ARGS` и
профиль. RNest принимает и молча пропускает всё, что не знает.

Окружение процесса:

- **Несколько процессов сразу.** Волна до 8 попыток с разными зёрнами, одновременно до
  `SHEETNEST_MAX_CONC` / «ядра ÷ потоки», не больше 8. Каждая работает в своей папке.
- **Приоритет BelowNormal.** SheetNest ставит его сам.
- **stdin не используется.** stdout и stderr читаются построчно (см. п. 6).
- **Отмена.** По «Стоп» дерево процессов убивается (`Kill(true)`).
- **Сторож.** Sparrow и RNest убиваются через `WatchdogSeconds` (минимум 60 с, обычно минуты).
  Любой другой движок (в версиях после 1.1.74) убивается через **120 с**, а если другая попытка того же листа
  уже ответила за T секунд — через max(60, 3·T). Результат убитой попытки выбрасывается; если не
  ответила ни одна попытка, лист не раскладывается.
- **Код выхода не смотрится.** Решает только наличие файла ответа.

## 4. Задание: `job.json`

Формат — экземпляр strip packing из jagua-rs (как у Sparrow 0.x, коммит `961ec31`). UTF-8, без BOM.

```json
{
  "name": "job",
  "strip_height": 1240.0,
  "items": [
    {
      "id": 0,
      "demand": 28,
      "allowed_orientations": [0.0, 90.0, 180.0, 270.0],
      "shape": { "type": "simple_polygon", "data": [[0.0, 0.0], [105.6, 0.0], [95.2, 495.0], [10.4, 495.0]] }
    },
    {
      "id": 1,
      "demand": 28,
      "allowed_orientations": [0.0, 90.0, 180.0, 270.0],
      "shape": { "type": "simple_polygon", "data": [[0.0, 0.0], [400.0, 0.0], [400.0, 95.6], [0.0, 80.0]] }
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `name` | всегда `"job"`; от него зависит имя файла ответа |
| `strip_height` | высота полосы, в единицах чертежа (мм или дюймы, как в проекте) |
| `items[].id` | индекс в задании: **0, 1, 2… подряд**. Это не номер строки деталей в проекте; обратно SheetNest переводит сам |
| `items[].demand` | сколько экземпляров положить. Положить надо все |
| `items[].allowed_orientations` | разрешённые углы в градусах, против часовой. **Если поля нет — угол любой** (свободное вращение) |
| `items[].shape.data` | внешний контур, `[x, y]`. **Уже расширен на половину зазора**. Без отверстий. Последняя точка не повторяет первую. Направление обхода не гарантировано. Начало координат — произвольная точка в системе координат чертежа детали (не обязательно угол рамки) |

Обычно в задании от 1 до нескольких десятков типов деталей и от единиц до сотен экземпляров. Задание
на один лист: SheetNest набирает партию примерно на 1.3 площади листа (`SelectBatch`), поэтому
нормально, что уложенная полоса длиннее листа.

## 5. Ответ: `output/final_job.json`

Движок пишет файл `output\final_<name>.json`, то есть `output\final_job.json`, **относительно рабочей
папки** (папку `output` создаёт сам движок).

```json
{
  "name": "job",
  "strip_height": 1240.0,
  "solution": {
    "strip_width": 2111.4,
    "density": 0.83,
    "run_time_sec": 0.4,
    "layout": {
      "container_id": 0,
      "density": 0.83,
      "placed_items": [
        { "item_id": 0, "transformation": { "rotation": 90.0, "translation": [495.0, 0.0] } },
        { "item_id": 1, "transformation": { "rotation": 0.0,  "translation": [500.0, 0.0] } }
      ]
    }
  }
}
```

SheetNest читает только:

- `solution.layout.placed_items[]`: `item_id`, `transformation.rotation`, `transformation.translation`;
- `solution.layout.density` (0…1): для выбора между попытками и полоски прогресса. Если поля нет,
  считается 0.

Остальные поля можно писать для совместимости, они не обязательны.

**Преобразование детали.** Берётся контур из задания (`shape.data` для `item_id`):

1. поворот вокруг **начала координат** (0, 0) на `rotation` градусов против часовой;
2. сдвиг на `translation` = [dx, dy].

То же преобразование SheetNest применяет к номинальному контуру детали. Поэтому:

- `rotation` должен быть одним из `allowed_orientations` и **точно соответствовать** положенному
  контуру. Не «примерно 90», и не поворот вокруг центра, пересчитанный неправильно;
- если движок вращает деталь вокруг центра или угла рамки, переведите результат в «поворот вокруг
  (0, 0) + сдвиг». Адаптер RNest для этого сверяет угол с фактически положенным контуром
  (`crates/nest-sparrow`).

**Где лежит раскладка, неважно.** SheetNest сдвигает всю раскладку так, чтобы её минимальные x и y
легли на поле листа. Важны только взаимное положение деталей и то, что по Y они помещаются в
`strip_height`.

**Положить не всё — допустимо, но плохо.** Экземпляры, которых нет в `placed_items`, просто остаются
в очереди на следующие листы. Деталь, которая физически не помещается в высоту полосы, SheetNest в
задание не отдаёт.

## 6. Прогресс

Каждая строка stdout и stderr, в которой есть `dens: <число>%`, двигает полоску прогресса в окне,
например:

```
[12.3s] iter 140  dens: 87.4%
```

Число — плотность в процентах, точка как разделитель. Строки без `dens:` игнорируются. Можно ничего
не печатать.

## 7. Что SheetNest делает после движка (движку об этом знать не нужно)

1. Переводит `item_id` обратно в деталь, поворачивает номинальный контур, ставит по `translation`.
2. Сдвигает раскладку на поле листа и уплотняет её «гравитацией» (`RasterCompact`).
3. Если в задании есть детали с общим резом, сводит кромки (`SnapDirectCommonLineEdges`).
4. Убирает с листа всё, что вышло за его край (`IsOutsideSheet`). Эти детали возвращаются в очередь.
5. Проверяет зазоры по номинальным контурам. Деталь, которая стоит слишком близко, тоже снимает
   (`DeferUnfit`).
6. Кладёт мелкие детали в отверстия, дозаполняет лист (fill-up, свободное место), раскладывает
   оставшиеся детали на следующие листы.
7. Из нескольких попыток (зёрен) выбирает лучшую (`PickBest`). Порядок сравнения:
   1. больше деталей на листе;
   2. длиннее общий рез;
   3. короче занятая длина вдоль длинной стороны листа;
   4. выше `density`;
   5. меньше зерно.

Значит, движку выгоднее всего **плотная, короткая по X упаковка без наложений**. Всё остальное
SheetNest доделывает сам.

## 8. Как проверить свой движок

В этой папке всё готово: `.\run-all.ps1 -Engine <exe>` прогоняет задания из `jobs/`, проверяет ответы
(`tools/check.mjs`) и сравнивает с эталоном (см. README.md). Ниже — то же самое руками и в SheetNest.

1. **Взять настоящие задания.** Запустите SheetNest с `SHEETNEST_DUMP_JOBS=<папка>`: каждый
   `job.json`, отданный движку, скопируется туда как `job_N.json`.
2. **Прогнать один файл руками**, в пустой папке:

   ```bash
   mkdir try1 && cd try1 && my-engine.exe -i ../job_1.json --max-iterations 300 -x -s 1 --workers 1
   ```

   Должен появиться `try1/output/final_job.json`.
3. **Подложить в программу.** Задайте `SHEETNEST_SPARROW=C:\путь\my-engine.exe` и запустите
   SheetNest. В окне будет работать ваш движок.
4. **Бенч на проекте** (из корня репозитория), с тем же движком:

   ```powershell
   $env:SPARROW_EXE = 'C:\путь\my-engine.exe'
   $env:SHEETNEST_BENCH_PROJECT = 'E:\Porta\skoiki.dnest'
   $env:SHEETNEST_BENCH_MARGIN = '5'
   $env:SHEETNEST_BENCH_SVG = 'C:\tmp\svg'   # картинка каждого листа
   dotnet test .\DeepNestSharp.CiTests\DeepNestSharp.CiTests.csproj -c Release --filter "FullyQualifiedName~NestSpeedBenchFixture.MeasureProjectNest" --logger "console;verbosity=detailed"
   ```

   Бенч печатает время, число листов, уложено / не уложено, использование и `unfit` по каждому листу:
   сколько деталей стоят слишком близко.
5. **Собрать задание из чертежей:** `rnest-make-job <out.json> <strip_height> <copies> <0|2|4|free>
   <чертежи>…` из `RNestEngine` (нужен Rust).

## 9. Частые ошибки

- **Записать ответ не туда.** Нужна папка `output` в **рабочей** папке процесса, а не рядом с `job.json`.
- **Вращать вокруг центра детали** и писать только угол. Детали встанут не там, наложатся, и
  SheetNest снимет их как непригодные.
- **Уменьшить зазор, считая, что SheetNest добавит его сам.** Не добавит: касание расширенных
  контуров — это и есть нужный зазор. Наложение даже на десятые миллиметра даёт красную деталь.
- **Падать на незнакомом флаге.** Не надо: флаги берутся из профиля пользователя и окружения.
- **Зависеть от часов.** Результат должен определяться заданием, бюджетом итераций и зерном, а не
  временем работы. Иначе одна и та же кнопка даёт разные раскладки.
- **Писать числа с запятой.** JSON читается с точкой; запятая как десятичный разделитель ломает разбор.
